# Retell voice bridge and public access for the 211 demo

* Type: design, implementation
* Scope: `dualuse/voice_bridge.py`, `scripts/retell_setup.py`, `tests/test_voice_bridge.py`, `docs/voice.md`; origin label: `dualuse/api.py`, `dualuse/ui.py`
* Related: [2026-10-17-008-reception-agent.md](2026-10-17-008-reception-agent.md) on branch `worktree-comms-211-demo`

## Context

* The 211 reception desk only accepts typed messages. The track partner is
  Retell AI, and the demo should let several people phone in at once while
  the operator desk shows the queue changing live.
* The server runs on the desktop; the demo is presented from a laptop on a
  different network, so the UI and the Retell callbacks need public HTTPS.
* The desk code (`holdqueue.py`, `reception.py`, `api.py`, `ui.py`) is being
  changed in parallel on `worktree-comms-211-demo`. This work is developed on
  branch `voice-retell-bridge` (from `d413d5f`) and must merge without
  touching those files.

## Decision

* A separate process, `dualuse/voice_bridge.py`, connects Retell to the desk
  through the existing REST API only. The REST endpoints are the contract:
  `POST /calls`, `POST /calls/{id}/say`, `POST /calls/{id}/silence`,
  `POST /calls/{id}/hangup`, `POST /calls/{id}/disconnect`,
  `GET /calls/{id}`. Integration is starting one more process.
  * Rejected: a router inside `api.py` (couples to queue internals that are
    changing) and a Retell-hosted LLM calling our tools (bypasses the
    desk's interview and ordering, and updates the board only on tool calls).
* Retell Custom LLM WebSocket at `/llm-websocket/{secret}/{retell_call_id}`.
  The path secret (`RETELL_WS_SECRET`) keeps strangers from opening calls.
  * Connection opens: create a desk call and speak the desk's welcome turn.
  * `response_required`: forward the caller's new transcript turns to
    `/say`, send a short acknowledgement at once (Claude takes seconds),
    then speak the assistant turns the desk added. Speech is always the
    desk's own text; the bridge never writes questions.
  * Caller speaks again while a turn runs: buffer the text and send it after
    the running turn, speaking only the latest result.
  * `reminder_required`: `POST /silence` and speak what the desk adds.
  * The desk call leaves `waiting` (operator reserved it): interrupt once to
    say an operator has the case and that voice transfer is not connected.
  * `ping_pong` is answered so Retell can reconnect.
* `POST /retell-webhook/{secret}` receives `call_ended`, verifies
  `X-Retell-Signature` (HMAC-SHA256 of raw body plus timestamp, keyed with
  `RETELL_API_KEY`, 5-minute window) and maps `disconnection_reason`
  `user_hangup` to `/hangup`, anything else to `/disconnect`. If no webhook
  arrives within 15 s of the socket closing, the bridge records a disconnect
  so no call is left waiting forever.
* Public access: two cloudflared quick tunnels (UI and bridge). Quick-tunnel
  URLs change on restart, so `scripts/retell_setup.py` writes the current
  bridge URL into the Retell agent and prints the numbers bound to it.
* Out of scope here: a password on the public UI and real voice transfer to
  a human.
* Sat 2026-10-17 afternoon PT, after testing on merged `main`:
  * `POST /calls` takes an optional `origin`, validated as `live` (default)
    or `phone`; the bridge sends `phone`. Free text is rejected so no
    client can write its own label into the operator's origin column. The
    operator desk marks phone calls "📞 phone" in the queue and expander, and
    on handoff says the caller's voice is not transferred. The UI header,
    About text, callback note and the API invariant now say phone calls come
    through the bridge when it runs, with no voice transfer to a person, no
    dispatch and no automatic callback.
  * Phone welcome: the bridge replaces the profile's Spanish and Chinese
    invitation (`welcome_extra`) with "This phone line works in English only."
    Typed calls are unchanged.
    * Rejected for now: setting the Retell agent `language` to `multi` (or a
      list) in `scripts/retell_setup.py`. `retell-sdk` 6.2.7 accepts both,
      but it was not tested live, needs a voice that speaks the desk's
      Spanish and Chinese replies, changes the live Retell agent during the
      demo, and whether `multi` recognizes Chinese was not checked. Tradeoff: Spanish and Chinese callers
      are not served by phone, but no caller is invited into a language the
      line cannot understand.
    * With the `cn-12345` profile the desk welcome is Chinese; the bridge
      only logs a warning. Phone demos use `la-211`.
