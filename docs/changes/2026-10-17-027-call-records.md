# Call records workspace with a live intake checklist

* Type: implementation
* Scope: `dualuse/ui.py`, `tests/test_ui.py`, `docs/architecture.md`, `README.md`, `docs/submission.md`
* Related: [short welcome and fixed intake](2026-10-17-025-short-welcome-fixed-intake.md)

## Context

* On Sat 2026-10-17 at about 18:45 PT the user asked whether the web page shows what the desk gathers from a call: complete records of finished calls, and a summary of the intake questions the agent asks. Ideally the summary would update live, for example as soon as a caller states an address.
* Before this change the desk already rebuilt its summary card from the latest extraction on every `GET /state`. **Caller details** showed it with a 2 s refresh, but only for waiting calls, as plain text. Finished, hung-up and disconnected calls had no record view. The user chose a UI-only change: no change to the extraction schema or the API.

## Decision

* A new sidebar workspace, **Call records**, refreshes every 2 s:
  * a table of every call on the desk, newest first, ended calls included;
  * a picker whose labels stay fixed while the status and tier change, so the operator's choice is not dropped;
  * a checklist of the six intake questions from [intake.md](../../dualuse/playbooks/intake.md), with the full conversation beside it.
* Each checklist row shows ✅ with the extracted answer, or ⏳ while unanswered:
  * Situation counts as answered when `enough_information` is true.
  * Safety counts as answered when it is danger (including `life_threat_now`) or no immediate danger.
  * Location, people and need count as answered when their fields are filled.
  * The medical or mobility question has no extracted field. Its row says so and points to the conversation. It is not counted in "N of 5 answers extracted".
* An orange "updated by caller message N" mark shows on each answer that changed after the caller's latest message, as this browser tab saw it. The first look at a call is the baseline, so only changes seen while someone watches are marked. Changes are tracked in the Streamlit session; the desk keeps no field history.
* The caller page and the record share one conversation renderer. Caller words and extracted text go through `literal`, as elsewhere in the UI.

## Verification

* Two new AppTest tests in `tests/test_ui.py`:
  * the table lists a hung-up call after a newer waiting one, and its record keeps the welcome and the caller's words;
  * the checklist fills in over three turns, the mark moves to the answer each message changed, and `#` in a location stays literal.
  * Both failed before the change and pass with it.
* Full suite: `bash scripts/uv-run.sh python -m pytest -q` in WSL, **496 passed in 91.15 s**.
* Browser check on a test desk (API 8093, UI 8593, model mode, own SQLite file), Sat 2026-10-17 about 18:55 PT:
  * "I see smoke coming from the building next door" took a 4.8 s turn. The record showed Situation answered, 1 of 5.
  * "It's at 1200 Wilshire Boulevard, nobody is hurt as far as I can tell" took 2.6 s. On the next refresh Location read `1200 Wilshire Boulevard` with the orange mark.
  * Situation was marked too, because Claude reworded it, which is a real text change.
  * Safety stayed unanswered: Claude left `safety` unknown for the hedged answer. That is the existing extraction behavior, not changed here.
  * The hung-up call's record showed its checklist and full conversation. The browser console showed no errors.
